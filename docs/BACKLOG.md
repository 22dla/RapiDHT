## Рабочие машины

| | 💻 Ноутбук | 🖥 Десктоп |
|---|---|---|
| CPU | Intel Core i7-1360P (13th Gen, 4P+8E, 2.2 ГГц базовая) | Intel Core i5-12400 (12th Gen, 6P, без E-ядер) |
| RAM | 16 ГБ | 32 ГБ |
| GPU | нет (встроенная Iris Xe, CUDA недоступна) | NVIDIA GeForce RTX 3060 Ti, 8 ГБ, Ampere sm_86 |
| ОС | Windows 11 | Ubuntu |
| Роль | CPU-сборка и тесты (MSVC или WSL2), Python-прототипы, статьи | CUDA, бенчмарки, LBM, обучение сетей |

Практические следствия:
- FP64 на 3060 Ti медленнее FP32 в ~64 раза → всё GPU-счётное — в `float`, двойная точность только в эталонах/тестах.
- 8 ГБ видеопамяти: 3D-объём в `float` до ~800³ с одним рабочим буфером; обучение 3D-сетей — патчи 64³–128³, смешанная точность.
- На ноутбуке у P- и E-ядер разная скорость: для замеров фиксировать `OMP_NUM_THREADS=4` и `OMP_PROC_BIND=close`, иначе разброс.

## E1. Свёртка и фильтрация (P1) — фундамент для всего остального

- [x] **B-101** 💻 Режим «сепарабельное DHT» (без прохода Брейсуэлла) + API `ConvolveEven(volume, kernel)`.
  Теорема: для ядра, чётного по каждой оси, `S(f*g) = S(f)·S(g)` (проверено численно, ошибка ~1e-14).
  *Готово, когда:* тест против прямой циклической свёртки на 1D/2D/3D, float/double, CPU.
  Сделано: `HartleyTransform::ForwardSeparable`, `<rapidht/convolution.h>` (`EvenKernelConvolution`, `IsEvenPerAxis`), `tests/test_convolution.cpp` (12 тестов: определение, самообратность, гаусс и «шероховатое» чётное ядро против прямой свёртки, float, отказ на нечётном ядре).
  Замер (Linux-среда ноутбука, 2 потока, float): сепарабельное vs истинное DHT — 27 vs 44 мс на 128³ (−38%), 416 vs 1185 мс на 256³ (−65%).
- [ ] **B-102** 🖥 То же на GPU; замер выигрыша от отказа от Брейсуэлла (ожидаемо −4.9 мс и −1 буфер при 512³).
- [ ] **B-103** ⚙ Линейная (не циклическая) свёртка: паддинг + нормированная свёртка у краёв (делить на свёртку маски).
- [ ] **B-104** ⚙ Ядра в физических единицах с учётом анизотропного вокселя `(dx, dy, dz)`: гаусс, Баттерворт, сферическое окно.
- [ ] **B-105** 🖥 Бэкенд `Modes::GPU_FFT` (cuFFT R2C → `Re−Im`) и автовыбор быстрейшего; честное сравнение в `benchmarks.md`.
- [ ] **B-106** ⚙ CPU: пачки линий + SIMD поперёк линий, без аллокации на линию. Цель — ≤1.5× от FFTW.
  Находка: `BracewellTransform3DCPU` стоит ~65% времени на 256³ — внешний цикл по самой быстрой оси (`y` по `Width`) и `collapse(3)` дают страйдовый доступ, плюс копия всего объёма. Переставить циклы (k→j→i), без `collapse`, писать по плоскостям.
- [ ] **B-107** R Эксперимент «смещение границ»: булевы модели с известной истиной; 2D-послойная vs 3D-фильтрация vs анизотропная диффузия/NLM; метрики — смещение интерфейса, пористость, наведённая анизотропия.

## E2. Поля функционалов и тензоров Минковского (P1)

- [x] **B-201** 💻 CPU-эталон: индекс конфигурации 2×2×2 → веса (табл. 2 диссертации) → 4 «плотности»; глобальные ФМ = сумма.
  *Готово, когда:* шар, куб, тор (χ=0), полый шар (χ=2) дают известные значения в пределах дискретизационной ошибки.
  Сделано: `<rapidht/minkowski.h>` — `MinkowskiConfigurationWeights`, `MinkowskiFunctionals` (границы Periodic/Empty), `MinkowskiDensities<T>` (4 плоскости, центровка Vertex/Voxel); `tests/test_minkowski.cpp` (14 тестов). Веса выводятся из подсчёта клеток объединения замкнутых кубов (Michielsen & De Raedt, Phys. Rep. 347 (2001) 461: V = n_c, S = −6n_c + 2n_f, M = π(3n_c − 2n_f + n_e), χ = −n_c + n_f − n_e + n_v), табл. 1–2 диссертации — независимые данные в тесте.
  Сверка табл. 2: все 22 класса × 4 веса верны (столбцы = 8V, 4S, 8M/π, 8χ). Замечания к тексту диссертации: в табл. 1 нет индекса 8 (одиночный воксель, класс 1); 22 класса — орбиты полной группы куба (с отражениями), только повороты дают 23; передний план 26-связен, фон 6-связен. S и M на гладких поверхностях завышены ≈ в 3/2 раза (шар r = 14: 1.52 и 1.50) — учесть в B-204 и при сравнении с формулами Майлса. Куб с тремя сквозными пересекающимися туннелями: род 5, χ = −4 (проверено).
- [x] **B-202** ⚙ Поля = 4 свёртки плотностей со сферическим окном через B-101 (не 22/256 свёрток). Банк масштабов: одно прямое преобразование на поле.
  Сделано: `EvenKernelBank<T>` (`convolution.h`: 1 + K сепарабельных преобразований на K ядер вместо 2K); `MakeWindow<T>` — шар (центры вокселей в радиусе, r < N/2) и гаусс (σ = r, сумма по периодическим образам — любой радиус, окно гладкое и чётное); `MinkowskiFields<T>` (`minkowski.h`) — плотности с центровкой Voxel × банк окон, нормировка Sum или Mean (на вес окна: локальная доля объёма, удельная поверхность...), выход 4·K полей, порядок [функционал][масштаб]. Тесты: банк = прямая циклическая свёртка для каждого ядра; шар-поле = перебор по шару (double 1e-9, float 2e-3); полный объём → доля 1, остальное 0; сумма поля по пространству = вес окна × глобальный функционал; поля коммутируют с центральной инверсией (шар и гаусс); отказ на плохом радиусе и размере. Всего 73 теста.

- [ ] **B-204** ⚙ Валидация формулами Майлса для булевой модели шаров (плотности ФМ в замкнутом виде).
