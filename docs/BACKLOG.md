## Рабочие машины

| | 💻 Ноутбук | 🖥 Десктоп |
|---|---|---|
| CPU | Intel Core i7-1360P (13th Gen, 4P+8E, 2.2 ГГц базовая) | Intel Core i5-12400 (12th Gen, 6P, без E-ядер) |
| RAM | 16 ГБ | 32 ГБ |
| GPU | нет (встроенная Iris Xe, CUDA недоступна) | NVIDIA GeForce RTX 3060 Ti, 8 ГБ, Ampere sm_86 |
| ОС | Windows 11 | Ubuntu |
| Роль | CPU-сборка и тесты (MSVC или WSL2), Python-прототипы, статьи | CUDA, бенчмарки, LBM, обучение сетей |

Практические следствия:
- FP64 на 3060 Ti медленнее FP32 в ~64 раза → всё GPU-счётное — в `float`, двойная точность только в эталонах/тестах.
- 8 ГБ видеопамяти: 3D-объём в `float` до ~800³ с одним рабочим буфером; обучение 3D-сетей — патчи 64³–128³, смешанная точность.
- На ноутбуке у P- и E-ядер разная скорость: для замеров фиксировать `OMP_NUM_THREADS=4` и `OMP_PROC_BIND=close`, иначе разброс.

## R. Новые направления (исследовательские спайки, 1–2 недели каждый)

- [ ] **R-1** 🖥 **3D Hartley Neural Operator для течения в пористой среде.** HNO предложен в arXiv:2606.24851 (Sulskis & Ravi, июнь 2026, кода нет): вывод — для эллиптических самосопряжённых операторов вещественный базис выигрывает. Течение Стокса/Дарси именно такое. Спайк: FNO vs HNO на 64³ синтетике (геометрия → поле давления/скорости, k), память и точность.

- [ ] **R-3** 🖥 **Поля ФМ в космологии**: локальные ФМ-карты как каналы CNN для вывода параметров на CAMELS/Quijote (глобальные ФМ уже работают — arXiv:2501.01698).
- [~] **R-4** 🖥 **Хартли на GPU со скоростью cuFFT и без дополнительной памяти: разложение плотной матрицы на маленькие.** Плотная матрица `cas` по оси — 2N операций на элемент (1024 при N = 512, 412 GFLOP на 512³): даже на 100 % пика это ≥ 25 мс против 12 мс у cuFFT. Кули–Тьюки в матричной записи сохраняет умножения матриц, но маленьких: N = N₁·N₂, шаг 1 — DHT длины N₁, шаг 2 — по парам (k₁, N₁−k₁) поворот, DHT длины N₂ по столбцам и пересборка (столбец N₁/2 — матрица со сдвигом на полшага). 2(N₁+N₂) операций на элемент — 96 при 512 = 32·16, в 10.7 раз меньше. Вывод и формулы — `src/internal/factored.h`.
  Почему это может обогнать cuFFT: линия длиной ≤ 2048 целиком в общей памяти блока, ось — одно чтение и одна запись; Брейсуэлл на месте по орбитам — ещё один проход. Итого 4 прохода по объёму (≈ 2.4 мс каждый на 512³ f32) ≈ 10 мс при нулевой дополнительной памяти (у cuFFT 12 мс и ~1 ГБ, у матричного пути 44 мс и 556 МиБ). Хартли вещественный — на тензорных ядрах ему не нужна эмуляция комплексного умножения, которую платят FFT на тензорных ядрах (tcFFT, FlashFFTConv).
