# RapiDHT — заметки для Claude

Библиотека многомерного дискретного преобразования Хартли (C++17; CPU — OpenMP, GPU — CUDA/cuBLAS) и основа исследований по цифровому анализу пористых сред. Автор — Евгений Волков; общение по-русски, код, комментарии и сообщения коммитов — по-английски.

## С чего начать
- Что делать: `docs/BACKLOG.md` — задачи с ID (B-xxx, R-x), приоритетами, машиной (💻/🖥) и критериями «готово, когда». Перед работой найди задачу там, после — обнови её статус и добавь строку в «Журнал».
- Цифры производительности и их методика: `docs/benchmarks.md`. Новые замеры — с указанием машины, точности и числа потоков.
- Главный исследовательский трек — R-1 (3D Hartley Neural Operator для течения в пористой среде).

## Машины
| | 💻 Ноутбук | 🖥 Десктоп |
|---|---|---|
| Железо | i7-1360P, 16 ГБ, без дискретной GPU | i5-12400, 32 ГБ, RTX 3060 Ti 8 ГБ (sm_86) |
| ОС | Windows 11, Visual Studio 2022 | Ubuntu; CUDA 12.4, системный GCC новее 13 |
| Пресет | `cpu-msvc` | `cuda-local`, `bench-local`, `dev-local` |

Пресеты `cpu-msvc` и `*-local` живут в `CMakeUserPresets.json` (не в git, на каждой машине свой):
- `cpu-msvc` задаёт генератор «Visual Studio 17 2022». Базовый `cpu` генератор не задаёт, и VS Code тогда подставляет «Unix Makefiles», что на Windows падает.
- `*-local` задают `gcc-13`/`g++-13`: CUDA 12.4 не принимает более новый GCC, а смешение двух GCC даёт ошибку линковки `__cxa_call_terminate` только в Release.

## Сборка и тесты
```bash
# десктоп (GPU)
cmake --preset cuda-local && cmake --build --preset cuda-local -j && ctest --preset cuda-local
# Linux без GPU
cmake --preset cpu && cmake --build --preset cpu -j && ctest --preset cpu
```
```powershell
# ноутбук (Windows)
cmake --preset cpu-msvc; cmake --build --preset cpu-msvc; ctest --preset cpu-msvc
```
Ожидается 48 тестов; без GPU 12 из них пропускаются (`SKIP_IF_NO_GPU()`), на десктопе должны выполняться все.

## Правила кода
- Форматирование — `clang-format-18` по `.clang-format`; CI падает на любом расхождении. Перед коммитом: `clang-format-18 -i` на изменённых `.h/.cpp/.cu` (кроме `3dparty/`).
- Предупреждения — ошибки в пресете `dev` (`RAPIDHT_WARNINGS_AS_ERRORS=ON`); новый код должен собираться без предупреждений на GCC и MSVC.
- Публичный API — Doxygen-комментарии в `include/rapidht/`; публичные заголовки не должны упоминать CUDA-типы (состояние устройства — за `Impl`).
- Тесты проверяют математику, а не только обратимость: сверка с прямым вычислением определения O(N²) (`tests/test_support.h`) и аналитическими парами. Любой новый алгоритм — с тестом против эталона, в float и double, на неквадратных размерах.
- OpenMP: MSVC поддерживает только OpenMP 2.0 — индекс `parallel for` должен быть знаковым целым, без `collapse` на непрямоугольных циклах.
- Соглашения преобразования: прямое ненормированное, обратное = прямое × 1/N; хранение `i + W*(j + H*k)`; размеры — степени двойки; `height == 0` → 1D, `depth == 0` → 2D.

## Железо: что помнить
- На 3060 Ti FP64 примерно в 64 раза медленнее FP32: GPU-счёт в `float`, `double` — для эталонов.
- 8 ГБ видеопамяти: объём 512³ float = 512 МиБ на буфер; 3D-сети — патчи 64³–128³, смешанная точность.
- Замеры на ноутбуке: `OMP_NUM_THREADS=4 OMP_PROC_BIND=close` (P- и E-ядра дают разброс).

## Git
- Работаем в `master`, по коммиту на задачу бэклога; ветка — только для рискованных переделок, и об этом нужно предупредить заранее.
- Сообщения коммитов — по-английски, в повелительном наклонении, как в истории (`Add …`, `Fix …`, `Refuse …`); в теле — зачем, и строка `Backlog: B-xxx`.
- Не включай в свой коммит чужие незакоммиченные изменения; добавляй файлы поимённо, не `git add -A`.
- Remote по SSH (`git@github.com:22dla/RapiDHT.git`); пушит автор, если не попросил иначе.
- Из Linux-окружения поверх Windows-папки нужен `core.autocrlf=true` (прописан в `.git/config`), иначе git видит ложные изменения CRLF во всех файлах.
